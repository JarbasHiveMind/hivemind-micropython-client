# AGENTS.md — `hivemind-micropython-client`

Guidance for AI coding agents (and humans) working in this repository. Read it
fully before making changes. It encodes conventions that are not obvious from the
code and that, if ignored, produce work that will be rejected.

## Repo

A pure-Python HiveMind satellite client for MicroPython 1.20+ and CPython
3.10+, from one shared codebase. It speaks the HiveMind wire protocol
(handshake, encrypted messaging, binary audio frames) so a microcontroller
(ESP32, Raspberry Pi Pico) can act as a satellite without running OVOS
on-device. Part of the [HiveMind](https://github.com/JarbasHiveMind) ecosystem
— a protocol for connecting satellite devices to a hub running
[OpenVoiceOS](https://github.com/OpenVoiceOS). The hub is
[HiveMind-core](https://github.com/JarbasHiveMind/HiveMind-core); the
reference client is
[hivemind-websocket-client](https://github.com/JarbasHiveMind/hivemind-websocket-client),
against which this client's conformance tests validate byte-for-byte interop.

## Layout / build / test

- Package: `hivemind/` (`__init__.py`, `client.py`, `crypto.py`, `noise.py`,
  `binary.py`). This is a MicroPython package installed on-device via `mip`
  (see `package.json`) — it has no CPython packaging (no `pyproject.toml`,
  no pip install of itself). Tests live in `test/` (check before adding — do
  not create a second test directory).
- The CPython test run needs the reference stack and optional accelerators,
  listed in `test-requirements.txt` (`hivemind-bus-client`, `ovos-bus-client`,
  `poorman_handshake`, `z85base91`, `cryptography`, `websockets`, `pytest`).
  Set up a throwaway environment inside your clone; never touch a shared venv:
  `python3 -m venv .venv && VIRTUAL_ENV=$PWD/.venv uv pip install -r test-requirements.txt --prerelease=allow`
- Run the suite in the foreground with the repo root on `PYTHONPATH` (so the
  on-device `hivemind` package is importable): `PYTHONPATH=. pytest test/ -v --tb=short`
- CI additionally `py_compile`s every module in `hivemind/` and `examples/`
  as a MicroPython-syntax sanity check — do not introduce CPython-only syntax
  (walrus in odd positions, match statements, f-string nesting tricks) without
  checking it compiles under that job too.
- `uv`, never `pip`. If latest prereleases fail to install or resolve, that is
  a bug to FIX at the source, not to work around with a pin downgrade.

## Dependencies

- **Floor pins only** (`>=X.Y.Za1`), bumped when a feature or fix is actually
  needed — with a one-line comment saying why. No upper caps unless a specific
  released version is genuinely broken (say which and why). `test-requirements.txt`
  already follows this for the reference-stack pins.
- **No lockfiles, ever.** Target the latest alphas (`--prerelease=allow`).
- The on-device `hivemind` package itself has zero runtime dependencies — that
  is a hard constraint, not an oversight. `test-requirements.txt` pins exist
  only to run the CPython test suite; never add a runtime import that needs a
  package MicroPython/`mip` cannot install on a microcontroller.
- Never install from git — depend on a published PyPI alpha for anything that
  does land in `test-requirements.txt`.
- Apache-2.0. Do not add GPL/AGPL dependencies.

## Tests

- Adversarial by default. A regression test must **fail before the fix and pass
  after** — prove it by reverting only the source (`git apply -R`, never
  `git stash` across worktrees) and watching the test flip.
- Tests must be mutation-proof: gutting the feature must fail the test. A test
  that only asserts a mock was called, without asserting the real behaviour, is
  weak — note it.
- Never skip a test because an optional dependency is missing.
- CI green is permission to review, not to merge. A non-trivial change gets an
  adversarial review before it lands.
- `test_conformance.py` and `test_noise_integration.py` validate byte-for-byte
  interop against the reference HiveMind stack — treat a failure there as a
  wire-compat break, not a flaky test, until proven otherwise.

## Repo-specific rules

- This client speaks the HiveMind wire protocol described in the README's
  handshake diagram: legacy v0-v2 password-derived session key, and protocol
  v3 Noise (`Noise_XXpsk2_25519_ChaChaPoly_SHA256` / `Noise_KKpsk0`) when a PSK
  is provisioned. Both must stay byte-for-byte compatible with `hivemind-core`
  and `hivemind-websocket-client` — do not change wire framing, encodings, or
  key derivation without cross-checking the reference client and the
  conformance fixtures in `test/noise_fixtures.json`.
- `noise_static_key` and the learned `server_noise_key` (TOFU pin) are the
  device identity; a caller that persists and reuses them keeps the same
  node identity and pin across reconnects — do not add code that silently
  regenerates or drops a persisted key.
- Bad credentials should fail fast, not reconnect forever — this is the
  standing HiveMind client-library rule. As shipped, `_receive_loop` treats
  every disconnect the same way and unconditionally schedules `_reconnect()`
  whenever `reconnect_ms > 0` (`hivemind/client.py`, `_receive_loop` /
  `_reconnect`); it does not distinguish an auth-rejection close (1008) from a
  transient network drop, so a wrong access key or password currently causes
  an infinite reconnect loop instead of a fast failure. Do not paper over this
  with a doc note — fixing it (surfacing the close code and only retrying on
  non-auth failures) is open work, not a documented trade-off.
- Runs on two Python runtimes from one source tree (`uasyncio` vs `asyncio`,
  detected via `_MICROPYTHON`). Any change touching async control flow, byte
  handling, or stdlib usage must be sane under both — check the MicroPython
  1.20+ stdlib subset, not just what CPython accepts.
- Memory is scarce on-device (see the README's `MemoryError` troubleshooting
  note): avoid gratuitous buffering or large intermediate structures in
  `client.py` / `binary.py`; chunk audio and free eagerly the way the existing
  code does.
